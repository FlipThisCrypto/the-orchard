# ADR-0004: Central oracle for v1 — a transitional bridge, not the product

- **Status:** Accepted (2026-06-11); reclassified as TRANSITIONAL by ADR-0008 (2026-06-12)
- **Date:** 2026-06-11
- **Deciders:** Richard Aubrey (FlipThisCrypto)
- **Supersedes:** the per-operator local oracle as the *default operator story*
  (local oracle + dashboard remain the dev/test loop)
- **Related:** ADR-0003 (verifiable dataset), ADR-0007 (device curve),
  ADR-0008 (serverless target — governs how much to invest here),
  [`replay-protection.md`](../replay-protection.md),
  [`HANDOVER_2026-06-11.md`](../HANDOVER_2026-06-11.md) D1/D4

## Context

The original operator story assumed each operator runs the oracle locally
(USB serial → local dashboard → register → post). Two findings broke that as
the *network* story:

1. **On-device or per-operator DataLayer is infeasible.** DataLayer needs a
   Chia full node + DataLayer service (GBs of state, a funded wallet, an
   on-chain spend per root update). A DataLayer *mirror* is not lighter — it
   serves files generated by the DataLayer service and needs a wallet spend
   to register. None of that fits an ESP32 or a casual operator's PC.
2. **Operators should need zero extra hardware.** "Plant a Tree, point it at
   the network" is the product promise. Any design that asks operators to
   keep a PC running 24/7 fails it.

## Decision

One **central oracle**, run by the project, is the v1 ingestion point:

```
Tree (ESP32) --signed reading, HTTPS--> Central Oracle (small VPS / home box)
                                            |  per-Season batch
                                            v
                                  Chia DataLayer (ONE store,
                                  ONE root update per Season)
```

- **Trees stay "dumb but honest":** sign every reading with their device key
  (secp256r1 per ADR-0007), POST it, nothing else. Zero operator hardware
  beyond the Tree.
- **ONE DataLayer store for the whole network.** Per-Tree attestation rows
  are keys inside it. One batched root update per Season (~daily) — not
  hundreds of on-chain transactions.
- **Trust story:** you don't trust the oracle; you verify device signatures
  plus the on-chain Merkle root (`orchard-verify`, ADR-0003). The oracle is
  an *aggregator*, not an authority.

### Deployment shape (PoC)

- FastAPI (uvicorn) bound to loopback on a small Linux box, fronted by
  **Cloudflare Tunnel** (preferred: zero inbound ports, free TLS/WAF/rate
  limits) or Caddy + Let's Encrypt on a VPS. Full hardening runbook is
  delivered as `DEPLOY_ORACLE.md` (lands at `docs/DEPLOY_ORACLE.md` when the
  box is stood up).
- **Rate limiting** per-IP and per-node at the edge (WAF rule on
  `/readings`) and/or app layer.
- **Persistence:** SQLite + WAL is fine to a few hundred Trees; the DB URL
  is a setting and Alembic migrations make Postgres a config change, not a
  refactor (HANDOVER T4). Fleet expectation: 100–1,000 Trees within 6 months.
- `require_wallet_session=true` in production; `require_seq=true` once the
  fleet runs seq-capable firmware (replay protection, HANDOVER T3).

### Decentralization path

- **Keepers (v2):** independent verifiers re-checking device signatures
  against the published dataset — possible *because* readings are
  device-signed, not oracle-signed.
- **ADR-0008 (North Star):** uptime proof moves on-chain entirely (Tree
  singleton heartbeats, epoch vaults, permissionless crank). That ADR
  reclassifies this oracle as a **transitional bridge**: build the minimum
  oracle that unblocks testers; prioritize work that transfers (device keys,
  seq counter → heartbeat counter, Merkle claims, signed OTA). The oracle's
  end state is *deletion* (HANDOVER T24), not maintenance.

## Consequences

**Positive**
- Operators need zero extra hardware; onboarding is flash → claim → done.
- One root update per Season keeps on-chain cost flat regardless of fleet
  size.
- Local oracle + dashboard remain unchanged as the dev/test loop.

**Negative / accepted**
- The oracle is a central availability point until ADR-0008 lands — outages
  pause ingestion (mitigated: Trees buffer and retry; uptime credit is
  hourly, not per-reading).
- The project pays for and operates infrastructure for the bridge period.
- README and operator docs must lead with "point it at the network oracle,"
  relegating the local-oracle path to a development section.
