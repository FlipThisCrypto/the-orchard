### Checkpoint directive 2 — PR #1 on secp256r1, merged
- [PR #1](https://github.com/FlipThisCrypto/the-orchard/pull/1) merged at
  `7c9b3ff`. The dataset/firmware work was rebased onto main and reworked
  ed25519 → **secp256r1 (P-256), ECDSA/sha256, RFC 6979 deterministic,
  64-byte r‖s low-S, 33-byte compressed SEC1 pubkeys** (`900dba0`).
  - Firmware signs via mbedTLS `mbedtls_ecdsa_sign_det_ext` (bundled with
    ESP-IDF — the `rweather/Crypto` dep was removed); wroom + s3 build clean.
  - Python schema signs via `ecdsa` (RFC 6979) and verifies via
    `cryptography`; golden vectors regenerated.
  - **Cross-check test (ADR-0007 item 4):** `orchard_chia/tests/test_clvm_secp.py`
    runs CLVM `secp256r1_verify` (via `chia_rs.run_chia_program`) over our
    signatures — proving on-chain verifiability. Tampered sig / payload /
    pubkey are rejected (an unknown opcode would no-op-accept, so those
    rejections are what prove the real verifier ran).

### Checkpoint directive 3 — replay protection (T3), merged
- [PR #2](https://github.com/FlipThisCrypto/the-orchard/pull/2) merged at
  `45e339b` (`0d98947`). Per `docs/replay-protection.md`:
  - Firmware: NVS reservation-block `next_seq()` (256-block wear
    amortization); `seq` inside the HMAC-covered body.
  - Oracle: `Node.last_seq`; with `require_seq` on, a distinct stale body →
    409 and missing/invalid seq → 400; exact duplicates stay idempotent 202
    via the existing sig-dedup; resets on re-registration.
  - **`require_seq` defaults False** (staged rollout, mirroring
    `require_wallet_session`); `last_seq` is tracked passively while off so
    the flip never strands a fleet already sending seq.

### Checkpoint directive 4 — v0.4.8 tag + binary cleanup
- `b1f091d` bumps firmware to **0.4.8** (first build carrying secp256r1 + seq).
- [Release v0.4.8](https://github.com/FlipThisCrypto/the-orchard/releases/tag/v0.4.8)
  is published with, per env: an app-only `*.bin` (OTA) **and** a merged
  `*-web-*.bin` (full-flash, offset 0) + `SHA256SUMS.txt`.

  - `6bfb379` deletes the two committed `flasher/**/*.bin` (~2 MB) and points
    `flasher/manifest.json` at the v0.4.8 `*-web-*` release-asset URLs. Git
    history no longer grows per firmware version.
  - Binaries are **unsigned** — release notes say so; signed OTA is T7.
